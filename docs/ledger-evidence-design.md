# Ledger 증빙 수집·보관 설계 초안

검토일: 2026-11-12. 청구서·영수증·거래명세서를 사업장이 안전하게 모아 확인하도록 준비합니다. 이 문서는 운영 설계 확정이나 실사용 지침이 아닙니다. 현재 업로드·자동 수집·공개 다운로드는 제공하지 않습니다.

## 분리할 경계

1. **수집 권한과 출처**: 각 사업장이 자신의 계정·메일함·파일에 대한 권한과 제공자의 이용 조건을 확인합니다. 수동 등록, 제공자 API, 이메일 등 각각의 출처와 수집 시점을 구분하되 출처만으로 문서가 진짜이거나 결제됐다고 단정하지 않습니다. 개인 계정이나 다른 사업장의 자료는 권한 없이 수집하지 않습니다.
2. **안전한 입력**: 입력 크기 제한, 허용할 형식, 실제 형식 확인, 악성 파일 검사와 안전한 열기 방식을 정하고 검증해야 합니다. 파일명·확장자·사용자가 말한 형식만 신뢰하거나 서버에서 문서의 코드를 실행하지 않습니다. 실패한 업로드와 임시 파일의 위치·권한·복구도 정해야 합니다.
3. **원본 보호**: 원본은 공개 웹 경로 밖의 별도 저장소에 보관하고 무작위 내부 식별자와 바이트 해시를 사용합니다. 저장소 경로, 파일명, 원본, 접근 토큰과 조회 결과를 URL이나 로그에 남기지 않습니다. 저장소와 백업의 접근권한·암호화, 키 보관·교체, 보존 기간, 삭제 및 장애 복구를 별도로 정해야 합니다.
4. **접근 권한**: 토큰 확인 외에 현재 사용자와 사업장, 개별 문서 및 관련 기록의 읽기·등록·정정 권한을 매 요청에 확인해야 합니다. 현재 Ledger 권한은 DB 전체에 적용되므로 문서별 접근 정책으로 그대로 사용할 수 없습니다. 권한 회수와 파일 읽기 사이의 경합도 검증해야 합니다.
5. **사실과 중복**: 동일 해시는 같은 바이트라는 뜻일 뿐 같은 거래, 같은 시점의 결제, 정확한 출처 또는 승인된 증빙이라는 뜻은 아닙니다. 문서의 수집·검토·사실 연결, 결제 및 직원 선지출 정산은 각기 다른 단계입니다. 중복 후보를 자동 확정하거나 실제 결제·정산을 추론하지 않습니다.
6. **일관성과 복구**: DB의 문서 참조와 파일 저장이 중간에 하나만 성공할 수 있으므로, 확인 가능한 상태 전이·재시도·복구 계획이 필요합니다. 정합성이 불명확한 파일은 임의로 지우지 않습니다. 백업·복원 시 DB와 원본의 같은 시점 일치, 누락·변경, 권한과 외부 수집 상태를 함께 확인해야 합니다.

## 현재 실험 범위

[`@vintage/ledger-evidence-vault`](../packages/ledger-evidence-vault/README.md)는 **가상 바이트만** 로컬의 기존 폴더에 쓰고 읽기 전 크기와 SHA-256을 대조하는 독립 실험입니다. 파일명은 무작위로 생성하고 기존 파일을 덮어쓰지 않습니다. 인증, 문서별 권한, 업로드, DB 연결, 출처 확인, 파일 형식·악성코드 검사, 암호화, 안전한 미리보기와 백업 복구는 구현하지 않았습니다. 파일 시스템의 접근권한과 경로의 신뢰성도 확인하지 못합니다. 실제 증빙을 넣거나 API에 연결하면 안 됩니다.
