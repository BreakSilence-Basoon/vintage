# 예정 근무 출퇴근 API 설계 초안

검토일: 2026-11-12. 이 문서는 구현된 설치 안내나 확정된 HTTP 명세가 아닙니다. 각 사업장이 독립적으로 설치하고 자신의 인증 제공자와 데이터를 관리하는 방향을 전제로 합니다. 다른 사업장을 위한 공유 서비스나 실제 운영 환경은 검증하지 않았습니다.

## 현재 구현과 경계

- 서버 내부 함수는 현재 활성 직원, 같은 사업장과 장소, 일정 버전, 기기 확인 값, 서버 시각을 확인합니다. 기록·감사·확인 값 사용은 한 트랜잭션에 저장됩니다.
- 확정된 결과는 같은 직원의 유효한 현재 자격과 원래 확인 값·행위·일정 버전으로만 조회합니다. 확인 값이 만료되거나 기기가 나중에 폐기되어도 이미 확정된 결과는 현재 직원 자격이 유지되면 조회할 수 있습니다. 이는 기기 사용을 다시 허용하는 것이 아닙니다. 복구 차단 중인 사본에서는 조회하지 않습니다.
- 같은 입력의 내부 제출은 이미 확정된 결과를 다시 반환할 수 있습니다. 잠금이나 권한 오류 등의 `unresolved`는 저장 실패를 뜻하지 않습니다. 진행 중에는 영수증이 보이지 않을 수도 있습니다.
- 인증 서명과 범위 검증, HTTP 경로, QR 발급·수집, 호출 빈도 제한, 실제 인증 제공자와 배포는 이 내부 함수에 포함되지 않습니다. 기존 관리자 쓰기 범위를 직원에게 부여하는 방식은 결정되지 않았습니다.

## HTTP 연결 전 필요한 조건

1. 각 요청의 서명·발급자·수신자·만료와 적절한 권한 범위를 검증하고, 요청 본문의 직원·사업장·역할을 신뢰하지 않습니다. 직원 출퇴근을 위한 권한 범위와 관리자 권한을 어떻게 나눌지는 인증 제공자와 함께 결정하고 시험해야 합니다.
2. 확인 값과 인증 정보는 URL에 넣지 않고 전송·프록시·오류·분석 로그에서 제외합니다. 암호화된 연결과 신뢰할 수 있는 프록시가 필요합니다. 요청 크기, HTTP 메서드, 응답 캐시, 쿠키 사용 시 출처 검사를 명확하게 제한합니다.
3. 기기의 비밀 전달·안전한 보관·교체·폐기, 확인 값 발급과 호출 빈도 제한을 구현하고 시험합니다. QR 중계는 가능하므로 이 확인만으로 물리적 위치를 보증하지 않습니다.
4. 시간 허용 범위는 설치자가 명시적으로 정해야 합니다. 서버는 신뢰할 수 있는 시계와 설정을 사용하고 클라이언트가 출퇴근 시각이나 정책을 정하게 하지 않습니다. 법적·업무 정책에 관한 기본값은 정하지 않았습니다.
5. 재시도는 원래 확인 값과 동일한 요청을 사용합니다. 조회가 비었거나 응답이 없다고 새 확인 값으로 무조건 재시도하지 않습니다. 확인 값 유실, 보존 기간 만료, DB 복원, 계속되는 잠금과 기기 교체 후 열린 기록은 별도의 확인·정정 절차가 필요합니다.
6. 여러 사업장의 설치·운영자가 스스로 관리할 수 있도록 인증 제공자 연결, DB 파일 권한과 암호화, 백업·복원, 서버 키 교체, 장애 대응 및 실사용 시험을 별도로 준비해야 합니다. DB 쓰기 권한자가 감사 내용을 변경할 수 있으므로 현재 감사는 변조 방지 기록이 아닙니다.

HTTP 응답 코드, 직원용 범위 이름, 보존 기간, 요청 제한 수치와 복구 후 정정 정책은 아직 정하지 않았습니다. 재시도 결과를 `confirmed`로 확인할 수 없는 경우를 실패 또는 성공으로 임의 변환해서는 안 됩니다.

참고: [OWASP REST Security](https://cheatsheetseries.owasp.org/cheatsheets/REST_Security_Cheat_Sheet.html), [OWASP Authorization](https://cheatsheetseries.owasp.org/cheatsheets/Authorization_Cheat_Sheet.html), [HTTP Semantics RFC 9110](https://datatracker.ietf.org/doc/html/rfc9110). 자료를 참고했다는 뜻이며 표준 인증 또는 보안 검증 완료를 의미하지 않습니다.
