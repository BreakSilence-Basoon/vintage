# 앱별 실행을 위한 준비

현재 [Timetable API](../apps/timetable-api/README.md)는 일부 조회와 제한된 관리자 변경을 지원하는 실험 단계이며, 실사용할 수 있는 완성 앱은 없습니다. 실제 설치와 운영 방법은 해당 앱을 검증한 뒤 안내합니다.

- `apps/`: 각각의 업무 앱
- `packages/`: 두 앱 이상이 필요로 하거나 별도 검증이 필요한 공통 기능
- 각 앱은 자신의 의존성과 실행 명령, 환경 변수 이름, 저장·인증 방법을 설명합니다.

Node.js 24와 Corepack으로 pnpm 10.11.0을 사용합니다. `corepack pnpm test`는 실제 앱이 아니라 테스트용 작은 패키지 세 개를 이용해 선택 실행과 오프라인 설치가 다른 앱을 포함하지 않는지 확인합니다. 실제 앱의 설치나 보안을 검증하는 시험은 아닙니다.

앱이 추가되면 해당 앱의 정확한 패키지 이름과 공통 의존성을 명시하고, pnpm의 `--filter <패키지명>...`으로 필요한 패키지를 선택합니다. 의존성 설치 범위와 실행 명령은 앱마다 독립 환경에서 검증하고, 해당 앱 안내서에 실제 동작을 기록합니다. 없는 패키지는 성공으로 오해하지 않도록 `--fail-if-no-match`를 사용합니다. [pnpm 필터 공식 문서](https://pnpm.io/filtering)

## 공개 전 확인

- 사설 Git 이력을 옮기지 않고 파일별 출처, 공개 권한, 제3자 라이선스 및 자산 사용 권한을 확인합니다. 이 저장소의 라이선스는 아직 미정입니다.
- 비밀번호, 토큰, 개인정보, 실제 고객·직원·거래 데이터, 내부 운영 설정은 예시와 테스트 자료를 포함해 공개하지 않습니다.
- 로그인과 서버 측 권한 확인은 기본적으로 접근을 거부하고, 설정 누락이나 인증 서비스 장애도 허용으로 바꾸지 않습니다. 허용·거부 양쪽을 시험합니다. [OWASP 접근 제어 지침](https://cheatsheetseries.owasp.org/cheatsheets/Authorization_Cheat_Sheet.html)
- 공개 대상 앱마다 필요한 서비스, 설정 값의 이름, 비용 가능성, 데이터 보관·복구, 설치와 실제 검증 결과 및 알려진 제한을 안내합니다. 준비되지 않은 앱은 사용 가능하다고 표현하지 않습니다.
