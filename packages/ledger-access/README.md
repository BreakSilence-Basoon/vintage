# Ledger 인증·권한 검사 실험

이 패키지는 신뢰된 서버가 지정한 발급자·대상·클라이언트·키와 **서로 다른 읽기/쓰기 범위**로 서명된 JWT 접근 토큰을 검증합니다. 토큰의 발급자와 사용자 식별자로 호출자가 제공한 현재 권한 조회 함수를 매번 호출하고, 같은 사업장·활성 사용자·명시적 읽기 권한을 확인합니다. 쓰기에는 명시적 쓰기 권한도 필요합니다. 사용자 재활성화 기준 시각보다 이전에 발급된 토큰이나, 조회 도중 만료된 토큰은 거부합니다. 조회 실패와 알 수 없는 요청도 거부하며 토큰을 반환하거나 출력하지 않습니다.

권한 조회 함수와 토큰 검증 키는 요청자가 정할 수 없으며 설치자가 신뢰하는 서버 구성에서 제공해야 합니다. 조회 함수는 현재 권한의 정본에서 **정확히 한 사용자**의 자격을 반환하고 중복·불명확·장애 시 거부해야 합니다. 이 패키지는 그 정본을 제공하지 않으며, `active`, 권한, 사업장과 작업자 ID가 사실인지 독립적으로 확인하지 않습니다. 역할별 기본 권한이나 직원·외부인 구분을 자동으로 만들지 않습니다.

**이 검사는 저장소에 연결되지 않았고, 단독으로 안전한 API를 만들지 않습니다.** 검사 직후 권한이 회수될 수 있으므로 실제 읽기·쓰기와 재시도에서는 검증된 신원을 기준으로 현재 권한과 대상 기록을 같은 신뢰 경계에서 다시 검사해야 합니다. 특히 쓰기와 권한 변경이 경합할 때의 원자성은 아직 구현·검증하지 않았습니다. 토큰 자체의 제공자 측 철회, 키 교체, 실제 제공자와의 호환성, 브라우저 세션, 암호화 전송, 파일 권한, 외부 API와 실사용은 미완료입니다. 테스트 키와 자격은 가상 자료이며 실제 거래를 넣거나 사용하면 안 됩니다.

토큰 검증은 공통 [`@vintage/access-token`](../access-token/README.md)의 RS256 JWT 접근 토큰 지원을 그대로 사용합니다. [RFC 9068](https://www.rfc-editor.org/rfc/rfc9068.html)과 [OWASP 권한 검사 지침](https://cheatsheetseries.owasp.org/cheatsheets/Authorization_Cheat_Sheet.html)을 참고했으며, 모든 인증 제공자 호환이나 보안 인증을 의미하지 않습니다.
