# 가상 증빙 파일 실험

이 패키지는 `acknowledgeSyntheticOnly: true`를 명시한 **신뢰된 로컬 코드**에서만 기존 폴더에 가상 바이트를 기록하고 무작위 식별자·SHA-256·크기를 반환합니다. 이 표시는 실제 자료인지 자동 판별하지 못합니다. 읽을 때 파일과 크기·해시를 다시 확인합니다. 단일 파일은 1바이트 이상 8MiB 이하의 실험 제한이며 업무상 파일 크기 정책이 아닙니다. 같은 바이트라도 별도 파일로 저장되고 해시가 같다는 사실은 같은 거래라는 뜻이 아닙니다.

별도 가상 SQLite 목록에 확인된 참조를 등록하고 같은 작업 ID와 내용의 재시도를 구분하는 실험도 있습니다. 파일과 목록이 일치하는 수, 파일 누락, 읽기 실패 또는 내용 변경, 목록에 없는 파일, 예상하지 못한 항목을 건수로만 확인합니다. 목록에 등록하기 전 파일이 만들어졌더라도 자동으로 지우지 않고, 이미 알고 있는 동일 참조는 등록을 다시 시도할 수 있습니다. 이는 실제 Ledger DB나 거래·증빙 출처와 연결되지 않으며, 불명확한 파일의 소유자·진위 확인 또는 자동 복구를 하지 않습니다.

점검은 DB 읽기와 파일 시스템 조회를 하나의 원자적 스냅샷으로 만들지 못하므로 관련 쓰기를 중지한 신뢰된 오프라인 환경에서만 해석해야 합니다. 파일 조회 중 사라지거나 접근이 거부되면 실제 원인을 구별하지 못하고 `unreadableOrChanged`로 표시할 수 있습니다. 목록과 폴더 각각 최대 10,000개까지만 확인하는 실험 제한이 있으며, 초과하거나 검사 자체가 실패하면 정상으로 간주하지 않습니다. 건수가 0이어도 최신 거래나 외부 자료가 빠지지 않았다는 증거는 아닙니다.

인증이나 사용자·문서별 권한, HTTP 업로드·다운로드, 실제 Ledger DB·출처 연결, 암호화, 파일 형식·악성코드 검사, 안전한 열기, 운영 백업·복구는 없습니다. 경로·상위 폴더와 그 접근권한이 신뢰할 수 있는지 도구가 보증하지 않습니다. Windows에서는 파일 생성 모드가 ACL을 보장하지 않고, 플랫폼에 따라 심볼릭 링크 교체 경합을 완전히 막을 수 없습니다. DB와 원본 파일의 변경을 하나의 트랜잭션으로 처리하지 않으며, 갑작스러운 전원 중단 후의 내구성도 보증하지 않습니다. **실제 증빙을 넣거나 API에 연결하지 마세요.**

오류 시 이미 만든 불완전 파일이 폴더에 남을 수 있습니다. 임의로 삭제하거나 다른 파일로 덮어쓰지 않으며, 담당자가 보호된 위치에서 확인해야 합니다. 반환된 해시와 크기·식별자도 보호해야 하며 단독으로 진위, 사용자 권한, 출처 또는 원본 보존을 증명하지 않습니다. 자세한 범위는 [증빙 설계 초안](../../docs/ledger-evidence-design.md)을 참조하세요.
