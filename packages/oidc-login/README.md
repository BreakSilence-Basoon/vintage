# OpenID Connect 로그인 교환 실험

이 구성 요소는 신뢰하는 로그인 제공자와 Authorization Code + PKCE S256 교환, 메모리 세션 및 브라우저 쿠키 처리를 실험합니다. Timetable 서버의 선택적 연결은 가상 제공자로만 시험했으며, 실제 제공자와 사용자 화면은 아직 검증하지 않았습니다.

서버가 HTTPS 발급자·클라이언트 정보·고정 콜백·API 대상과 토큰 검증기를 설정해야 합니다. 매 로그인마다 임의의 state, nonce, PKCE 값을 만들고 브라우저에 연결할 별도 임의 값을 반환합니다. 콜백은 고정 주소, state와 브라우저 연결 값이 모두 맞아야 하며 한 번만 사용할 수 있습니다. ID 토큰 서명과 nonce를 확인하고, 접근 토큰도 별도로 검증해 두 토큰의 발급자와 사용자가 일치하는지 확인합니다. 요청에 쓰기 범위를 포함한다면 쓰기 범위까지 검사하는 별도 검증기가 필수입니다.

브라우저 어댑터는 연결 값과 불투명한 세션 ID에 HTTPS의 `Secure`, `HttpOnly`, `SameSite=Lax`, `Path=/` 쿠키를 사용합니다. 변경 요청과 로그아웃은 지정한 Origin을 요구합니다. 메모리 세션은 접근 토큰을 매번 다시 검증하며, 로그아웃 시 제거되고 서버 재시작 후 사라집니다. 제공자 측 토큰 철회와 다중 서버 간 세션 공유는 구현하지 않았습니다. 접근 토큰과 클라이언트 비밀은 서버 안에만 보관하고 로그·URL·브라우저 저장소에 남기면 안 됩니다. API는 현재 직원 자격도 매 요청마다 다시 검사해야 합니다.

서버 연결 시 고정된 공개 HTTPS 주소와 신뢰할 수 있는 프록시 설정이 필요합니다. 여러 `Set-Cookie` 헤더를 각각 전달하고, 인증 결과의 내부 요청 헤더를 외부 응답이나 로그에 노출하지 않아야 합니다. 이 모듈의 시험만으로 배포 환경의 TLS, 프록시, 쿠키 전달 또는 전체 CSRF 방어가 검증된 것은 아닙니다.

테스트는 가상의 제공자 응답과 메모리에서 만든 키만 사용합니다. 실제 제공자와의 호환성·계정 설정·요금·운영 환경은 검증하지 않았습니다. `openid-client`는 MIT 라이선스로 배포되며 이 저장소의 라이선스는 아직 미정입니다. 예를 들어 Auth0는 [RFC 9068 접근 토큰 프로필](https://auth0.com/blog/jwt-access-tokens-profiles-now-in-ga/)을 선택할 수 있다고 안내하지만, 이 프로젝트와 실제 연결한 사실은 없습니다.
